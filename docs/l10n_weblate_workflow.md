# Localization workflow (Weblate)

## Overview

- **Tool:** [Weblate — Linagora / twake-matrix](https://hosted.weblate.org/projects/linagora/twake-matrix/)
- **Bridge branch:** [`l10n`](https://github.com/linagora/twake-on-matrix/tree/l10n)
- **Source strings:** `assets/l10n/` (template file: `intl_en.arb`, see `l10n.yaml`)
- **Generated code:** `lib/generated/l10n` (`L10n` class) — this is generated by
  `flutter gen-l10n` from the ARB files. Weblate never touches generated code,
  only the ARB source files.

## Roles

- **Translator:** works only in the Weblate UI. Never edits ARB files directly
  on GitHub.
- **Maintainer:** rebases/pushes the `l10n` branch, triggers the Weblate
  update/pull, and opens the PR that merges `l10n` into `main`.

## Sync steps

### 1. Rebase `l10n` on top of `main`, then push

```bash
git fetch origin
git checkout l10n
git reset --hard origin/l10n   # or: git pull --ff-only
git rebase origin/main
git push origin l10n --force-with-lease
```

`--force-with-lease` is required because the rebase rewrites history on
`l10n`. Never use a plain `--force`.

**Caution:** Weblate also pushes commits to `l10n` on its own schedule. Before
rebasing, check Weblate's repository status (or lock/pause translation
commits for `twake-matrix` if the UI supports it) so a force-push doesn't
overwrite translator work that landed between your `fetch` and your `push`.
The `git reset --hard origin/l10n` step above ensures you rebase from the
actual latest remote state, not a stale local copy. If in doubt, re-run
`git fetch origin` and re-check for new commits on `l10n` right before you
push, in case Weblate committed while you were rebasing.

### 2. Have Weblate fetch the rebased `l10n`

- Open the Linagora Weblate project `twake-matrix`.
- Go to **Repository maintenance** → **Update** (pull from the `l10n` remote
  branch).
- This pulls in any new source strings that were merged into `main` since the
  last sync.

### 3. Translate and push from Weblate

- Translators complete translations for the languages that need updates in
  the Weblate UI.
- Weblate commits and pushes those changes back to the `l10n` branch on
  GitHub, using commit messages like `Translated using Weblate (French)`.

### 4. Open a PR from `l10n` into `main`

```bash
git fetch origin l10n
gh pr create --base main --head l10n \
  --title "[Weblate] Update L10n from" \
  --body "Sync translations from Weblate via the l10n branch."
```

The title follows the convention used by prior syncs (see PR #3252). If a
sync PR from `l10n` into `main` is already open, pushing to `l10n` updates
that existing PR automatically — don't open a second one.

### 5. Review and merge

- Review as a normal PR (diff should be limited to ARB files under
  `assets/l10n/`).
- Merge into `main` once approved.

## Troubleshooting

- **Merge conflicts in ARB files during rebase:** resolve so that any keys
  added or removed on `main` are reflected in every locale file (new keys
  present, even if untranslated and falling back to `en`), while keeping the
  existing translated values that came from `l10n`. Don't let `main`'s
  version of a locale file silently overwrite translations from `l10n`.
- **Weblate shows "outdated" / can't push:** trigger a Repository maintenance
  → **Update** again before doing more translation work in the UI.
- **Do not** hand-edit `intl_*.arb` files on `main` for locales that Weblate
  manages — those edits get overwritten (or conflict) on the next sync.

## Before a release

Check [`docs/adr/0036-release-process.md`](adr/0036-release-process.md) —
make sure the latest `l10n` → `main` PR has been merged before cutting a
release, so the release includes up-to-date translations.
